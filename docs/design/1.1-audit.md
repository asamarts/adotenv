# 1.1 audit

This page records the review of the 1.1.0 code base on 2026-11-02. It lists
the findings, the evidence, the corrections to the first review report, and
the planned 1.1.1 and 1.2.0 work. `AUD-1` and `AUD-2` are fixed on the
`prep-1.1.1` branch.

The review covered the core parser, model, edits, formatting, sorting,
references, resolution, loading, serde support, the CLI, the process crate and
the two adapters. It did not change public behavior except for the fixes
listed here.

## Method

The review used these checks:

```console
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
python3 scripts/check_docs.py
cargo llvm-cov --workspace --all-features --locked --summary-only
python3 conformance/check_adotenv.py --setup
```

It also used a scratch crate outside the repository with targeted cases for
loading, resolution, formatting, serde and the CLI. Measurements were taken
from release builds on the reference host with `/proc/self/status` and the
`resource` module.

Baseline evidence:

- `adotenv`, `adotenv-process` and `adotenv-cli` 1.1.0 are published; the
  adapters are 0.12.0.
- The latest CI, Docs, Release and Fuzz runs passed. The only recent failed
  run was the 1.0.1 release commit, which the next commit replaced.
- `cargo test --workspace --locked` passed. `cargo test --workspace
  --all-features --locked` also passed during the coverage run.
- Coverage was 95.75 percent of lines and 95.36 percent of regions. The lowest
  modules were `resolve.rs` at 89.9 percent of lines and `adotenv-cli/src/main.rs`
  at 94.5 percent.
- The conformance runner passed 80 cases and 20 profiles, with 463 applicable
  observations.
- `adotenv` had about 3,500 crates.io downloads and one recorded external
  adopter, `asamarts/alint`.

## What the review confirmed

The lossless document model, verified edits, formatting, sorting, comparison
and the parser presets held up under targeted and randomized checks. The review
found no edit that passed verification but changed unrelated meaning, no
parser panic on arbitrary UTF-8, and no UTF-8 boundary or span arithmetic
failure. The remaining risks are at the boundaries: loading raw tokens back
into a synthetic document, the resolution grammar compared with upstream
implementations, CLI file-system and report contracts, and resource use before
the existing limits apply.

### AUD-1: contextual loaded resolution is not lossless

`LoadedEnvironment::resolve_contextual` builds a synthetic file from the raw
key and value tokens of the winning declarations (`src/load.rs:1340-1358`)
and parses it with the load dialect. Two inputs change under that rebuild:

```text
Docker file:              A=x\r\r\nB=${A}z\n
loaded A:                 "x\r"
resolve_contextual A:     "x"          (wrong; the CR joins the appended LF)
resolve_contextual B:     "xz"
resolve_decoded A:        "x\r"        (correct)
resolve_decoded B:        "x\rz"
```

```text
Python file:              # c\n\u{feff}B=1\nA=${B}\n
loaded keys:              ["\u{feff}B", "A"]
resolve_contextual keys:  ["A", "B"], A = "1"
```

The first synthetic declaration sits at byte 0, so `BomPolicy::Strip` removes
a U+FEFF that belongs to the key. A key that is exactly U+FEFF makes the whole
rebuild fail with `dotenv.invalid-key` instead. Before 1.1.1,
`resolve_contextual` had no exact round-trip check, unlike `resolve_decoded`
(`src/load.rs:1195-1212`).

The fix starts the synthetic source with a blank line, adds one CR before the
line feed when a raw value ends with CR in an LF-only dialect, and verifies
every parsed key and value against the loaded record. A key or value that
cannot be reproduced is an error naming the key. The regression tests cover
Docker trailing CR, Python and Docker leading U+FEFF keys, a key that is only
U+FEFF, a bare key read as empty, and the existing quote and escape cases.
Fixed on the `prep-1.1.1` branch in `src/load.rs` with tests in
`src/load_tests.rs`.

### AUD-2: Compose and dotenv-expand operands used shell grammar

`Reference` scanning used to treat `'`, `"` and `\` inside `${...}` as shell
quoting. Compose and dotenv-expand stop the operand at the first `}` outside a
nested form and do not remove quotes. Because an unclosed reference is not
eligible, the scanner left it literal:

```text
source:                    A=${B:-do'nt}
adotenv compose:           "${B:-do'nt}"
compose-go 2.16.1:         "do'nt"

source:                    A=${B:?can't continue}
adotenv compose:           literal, no error
compose-go 2.16.1:         error
```

The second case was a required-variable check that did not run. The same
grammar changed `A=${B:-a\}b}` and `A=${B:-\$C}`. The fix uses operand
grammar for brace frames (first `}` outside a nested form; quotes and
backslashes are ordinary characters) and keeps shell grammar only inside
`$()` frames. A backslash
before a nested `$` in an operand is now ordinary text, so `A=${B:-\$C}`
expands the nested variable and keeps the backslash, matching the Compose
oracle. `Reference::escaped` and `ReferenceRules::escaped_dollar` were
updated: escaped contexts are double-quoted values and command payloads, not
brace operands.

Fixed on the `prep-1.1.1` branch. Tests in `src/reference_tests.rs` and
`src/resolve_tests.rs` record the Compose 5.6.0 / compose-go 2.16.1
observations for `do'nt`, `"quoted"`, `a\}b`, `\$C`, `\${C}` and the `:?`
message. A focused differential run of 130 operand, quote, backslash, brace
and required-message cases against the pinned Compose oracle found no
mismatches when resolution used `Unresolved::Empty`. The full resolution
conformance profile remains AUD-25.

`ExpandOptions::dotenv_expand()` has no pinned oracle. The current
dotenv-expand package (1000.0.0, from `dotenvx/dotenv-expand`) supports `:-`,
`-`, `:+` and `+`, but not `?` or `:?`; adotenv errors on those. It also
replaces unresolved references with empty, while every `ExpandOptions` preset
keeps them literal by default. Either pin dotenv-expand and add a conformance
profile, or describe the preset as an adotenv extension.

The same unresolved-reference difference applies to `ExpandOptions::compose()`:
Compose substitutes empty for an unset name inside a default, while the preset
keeps it literal. The documentation already says that `ReferenceRules::COMPOSE`
does not emulate Compose interpolation as a whole, but the resolution
conformance profile must use `Unresolved::Empty` or restrict its inputs.

### AUD-3: unchanged files are replaced

`fmt --write` calls `write_atomic` without comparing the output with the
source (`adotenv-cli/src/main.rs:865-879`). Verified with an already formatted
file: the inode and modification time changed. In a read-only directory the
command exits 2 even though no write was needed. `docs/design/cli.md:211`
says `--write` rewrites changed files. `set` has the same unconditional write
(`main.rs:1351-1357`). The fix is a no-change guard in both commands.

### AUD-4: read and replace resolve the path separately

`fmt --write` and `set` read the path with `read_text` (`main.rs:822`,
`1343`), then `write_atomic` canonicalizes a symbolic link again
(`main.rs:1484-1521`, `1575-1580`) and renames over the result. There is no
device and inode check. A symlink swap between the read and the replace can
send file A's content to file B. The recursive walker checks the link at
`main.rs:259-264` and then reads a path that can be replaced by a link. The
fix is to resolve once before reading and verify the identity before the
rename, or to open the target once and write through it.

### AUD-5: `diff` output for two files

`diff_streaming` sets `multi = paths.len() > 2` (`main.rs:980`), so the
`baseline -> file` header and `(no differences)` only appear with three or
more files. Verified: `diff base.env same.env` prints nothing and exits 0;
`diff base.env diff.env` omits the header. `docs/design/cli.md:148-152`
promises both for every candidate and uses two files in its example. The fix
is to emit the header for every candidate.

### AUD-6: recursive discovery reporting and duplicates

`walk_env_files` returns the first `read_dir` error (`main.rs:248-252`) and
`check` returns before producing a report (`main.rs:470-476`). With one
unreadable subdirectory, `check --format json -r walk` exits 2 with empty
standard output. That breaks the stable JSON report and the rule that `check`
and `fmt` process every file (`docs/design/cli.md:311`). Separately,
`check -r . sub` reports `./sub/.env` and `sub/.env` as two files, although
the report says found files are deduplicated (`docs/design/cli.md:110`). The
fix is to record discovery errors per path, continue, and deduplicate by
resolved path.

### AUD-7: formatting is not idempotent at a final lone CR

`src/format.rs:733-736` leaves lines that end with or follow a lone CR alone
for trailing-whitespace trimming. `src/format.rs:807-829` then removes that
same CR when `FinalNewline::Remove` is selected. The next format pass trims
the whitespace that the first pass preserved:

```text
U="multi\nline" \r  ->  U="multi\nline"   ->  U="multi\nline"
# comment  \r       ->  # comment          ->  # comment
```

This contradicts the `FormatResult` example at `src/format.rs:333-335` and the
next-parse guarantee in `docs/design/formatting.md:67-70`. The property test
excludes `Remove` from its idempotence assertion (`src/format_tests.rs:570`),
so the case is not covered. The fix is to make trimming agree with the final
CR removal and remove the exclusion.

### AUD-8: `exec::Shell` has no output bound

`src/exec.rs:184-204` uses `Command::output()`, which buffers the complete
standard output and standard error before resolution checks the result
(`src/resolve.rs:1429-1492`). A command that prints without end can exhaust
memory, and a command that never exits blocks resolution. The documentation
already limits this helper to trusted files, but the 1 MiB and 64 MiB limits
cannot contain a trusted command that runs away. Add a shell output cap that
streams and stops the child, and consider a timeout.

### AUD-9: resolution scans before applying limits

`src/resolve.rs:1293` builds the reference list before the value-size check at
`1300`. A `Reference` is about 152 bytes, so dense references allocate much
more than the input. Measured in a release build:

| Value | Peak RSS |
|---|---:|
| 0.8 MB of `\${M:-$A}` repeated | 71.7 MB |
| 1.6 MB of the same | 141 MB |

Both cases happen before `max_value_bytes` or `max_output_bytes` can reject.
`Entry::references()` has the same profile. Add a scan budget or charge while
scanning, and document the memory cost of the public reference API.

### AUD-10: one diagnostic per occurrence

`src/parser/decode.rs:267-282` creates a `TightHash` or `Backtick` diagnostic
for every character, and `src/parser.rs:1535-1551` creates one
`LoneCarriageReturn` diagnostic per CR. A 1 MB value of `#` used 58 MB in
`parse` against 13.8 MB in `parse_values`, with one million diagnostics.
`adotenv-cli check` uses `parse_with` (`main.rs:516`), so an adversarial file
can exhaust memory in a linter. Add a diagnostic budget or coalesce repeated
per-item warnings.

### AUD-11: `lookup_index` capacity

`src/model.rs:976-982` sizes the table from `document.entries().len()`, not
from the number of distinct keys. A file of 200,000 Node bare keys produced an
index with `len() == 0` that allocated about 12 MB. Count distinct keys first
or grow the table as keys are inserted.

### AUD-12: `Document::example` and the BOM

`docs/design/comparison.md:61-67` says an example keeps a BOM.
`src/example.rs:20` and `154-167` keep only indentation, a `#` and a line
ending for commented items. Under `BomPolicy::Keep` the first declaration is
commented out as a whole, so the BOM and the declaration are lost. Under
`BomPolicy::Error` the invalid item becomes `#`. The presets use `Strip`, so
the default path hides this. Decide whether to keep the BOM as a comment
prefix or correct the documentation.

### AUD-13: fragment re-encoding and U+FEFF

`Context::verify` parses `before + token + after` as a fragment
(`src/encode.rs:228-280`). The fragment starts at the item start
(`src/edit.rs:1092`, `src/format.rs:671`), so a leading U+FEFF is read as the
file's BOM and stripped. A key that is exactly U+FEFF then gives
`EditError::Unencodable` from `set`, and `format` silently leaves the value
unquoted. Parse the fragment with a dialect that does not strip a BOM, or add
a sentinel prefix and verify the result.

### AUD-14: mode `local`

`load_cascade_with_options` builds `.env`, `.env.local`, `.env.{mode}` and
`.env.{mode}.local` (`src/load.rs:1689-1694`); `load_cascade_values_with`
repeats it (`src/load.rs:1862-1867`). Mode `local` is valid (`src/load.rs:1960`)
and produces `.env.local` twice. Values are unaffected, but `entries()` and
`overrides()` report the same file overriding itself. Deduplicate the path
list while preserving order.

### AUD-15: `parse_values` and Compose's empty key

Compose accepts an empty key, as in `=x` or a bare last line. `Document::get("")`
returns that value, but `parse_values` skips it because it filters empty keys
(`src/parser.rs:563`). The loader also skips empty keys, so this is a parser
API difference. Document the exception or align the values-only API.

### AUD-16: `QuotedTail::Append`

The appended tail is added after the decode loop without
`normalize_newlines` or the Portable `#` and backtick warning scan
(`src/parser/decode.rs:47-71`). `EntryTokens::value` and `body` cover only the
quoted token, while `Entry::value()` and `value_span()` include the tail, so
the token API and the entry API disagree (`src/model.rs:210-217`). This is a
custom-dialect edge; document or fix it.

### AUD-17: BOM diagnostics and the line limit

When the first line exceeds `line_byte_limit`, the resource rejection runs
before BOM interpretation (`src/parser.rs:613-657`). `BomPolicy::Strip` then
reports no `ByteOrderMark` diagnostic and `BomPolicy::Error` reports no
`ForbiddenByteOrderMark`; the whole line becomes one `LineTooLong` item. The
public docs describe the BOM diagnostics without this precedence. Document
the order or emit the BOM diagnostic after the limit error.

### AUD-18: serde flatten errors

`with_context` is applied in `EntriesAccess::next_value_seed`
(`src/serde_support.rs:357-369`). Flattened fields are decoded later by
serde, so a conversion error from `deserialize_any` (`273-323`) reports
line 0 and no key. Verified with `#[serde(flatten)] rest: BTreeMap<String, u16>`
on `a=x`. Either attach context in the flattened path or document the
limitation.

### AUD-19: `adotenv-config` dotted keys

The adapter inserts keys unchanged into `config::Map`
(`adotenv-config/src/lib.rs:71-77`). `config` reads `.` as a nested path. With
`A=1` and `A.B=2`, `get_string("A.B")` works, but `A` becomes a table and
`get_string("A")` fails with a type error. The module documentation mentions
the separator but not the change of shape. Document it, or reject dotted keys,
or offer a nesting option.

### AUD-20: Windows environment rules

`adotenv-process::validate` (`adotenv-process/src/lib.rs:173-190`) and the
CLI copy (`adotenv-cli/src/main.rs:1424-1434`) reject empty keys, `=` and NUL.
Windows environment blocks are case-insensitive, so `Path` and `PATH` both
pass and one wins by sort order. The process value length limit is also not
checked. Add a platform-aware check and tests.

### AUD-21: process tests and the environment

The unit tests call `unsafe { apply(...) }` and read the environment
(`adotenv-process/src/lib.rs:288-337`) while other tests run in the same test
binary. `cargo test` runs tests in parallel, so the suite exercises the race
the crate documents as the caller's responsibility. Use one serialized test
or a separate test process.

### AUD-22: CLI option and test gaps

- A repeated `--dialect` leaves the second pair to the path parser, and
  `--dialect=node` is treated as a path. `--format=<value>` is documented;
  `--dialect=` is not, so this is an interface inconsistency rather than a
  broken promise.
- An unknown option such as `--jsn` is treated as a path instead of a usage
  error.
- `fmt --write --check` with an empty directory exits 0 before the conflict
  check.
- A temporary name `.{name}.adotenv-{pid}-{counter}` can exceed `NAME_MAX`
  for a long file name; verified with a 254-byte name.
- Several tests are weaker than their names suggest. The one-line JSON test
  checks a substring and a line count rather than parsing the JSON; the
  documented-schema test returns early when the docs directory is absent; a
  temporary-file test removes the directory before asserting the file is
  gone; the write-failure test skips when permissions are not enforced.

### AUD-23: DOTENV_EXPAND compatibility

The preset is named after dotenv-expand but has no pinned version or oracle.
The current dotenv-expand implementation (1000.0.0) expands `:-`, `-`, `:+`
and `+` and leaves `?` forms empty; adotenv errors on `?` and `:?`. It also
substitutes empty for unresolved names, where adotenv keeps them literal, and
it has its own `$$` and escape handling. Pin a version and add a profile, or
rename the preset and document the supported operators as an adotenv choice.

### AUD-24: secrets documentation

`LineIndex` derives `Debug` over the source (`src/position.rs:219-223`), and
`Group`/`Groups` derive `Debug` over document items. `src/lib.rs:137-141`
lists documents, items, entries, edit and format results, comparisons, loaded
environments and resolved values, but not these types. Add them to the
warning, or redact the source in `Debug`.

### AUD-25: conformance does not compare resolution

The conformance runner compares literal parser output. For Compose it excludes
sources containing `$` because the upstream parser always interpolates, and
the Rust probe calls `parse_with`, not `resolve`. The 463 applicable
observations therefore do not cover the reference scanner or resolution. That
is why AUD-2 survived. AUD-2 now has direct unit tests that record the pinned
oracle values, but the corpus still does not exercise resolution as a whole.
Add a resolution profile that calls `Document::resolve` with
`ExpandOptions::compose()` and compares the result with a curated set of
Compose interpolation cases. Add cases with quotes, backslashes, `$` in
operands, nested defaults and `:?` messages.

### AUD-26: evidence older than the code

`docs/design/performance.md` and `docs/design/test-audit.md` still describe
1.0.0. The 1.1.0 release changed `format.rs` and `sort.rs` substantially, so
the performance record and coverage table should be re-run. Mutation testing
last ran before the 1.0 edit-verification changes. The 1.1.0 fuzz evidence is
one manual run, not the four-run pattern used for 1.0.

### AUD-27: repository state

The local `main` branch is 59 commits behind `origin/main`. `prep-0.11` and
`pr3-criterion` are stale. Issue 13 describes 1.0 work that is complete and
should be closed or converted into the 1.1 evidence task. Issue 14 is the
linter and LSP incubation item.

## Corrections to the first review report

These points in the first report were wrong or imprecise and are corrected
here:

1. `adotenv-config`: the first report said `A.B` was unreachable and
   `get_table("A")` failed. In fact `get_string("A.B")` works and `A` becomes
   a table, so `get_string("A")` fails with a type error. The finding is the
   change of shape, not a missing child key.
2. CLI JSON test: the first report said the first disjunct of
   `assert!(!json.contains('\n') || json.lines().count() == 1)` is always
   false and the test never validates JSON. The assertion does check a line
   count; it does not parse the JSON. The weaker point is the missing parse.
3. `--dialect=node`: the first report implied a documented option form.
   Only `--format=<value>` is documented. Treat `--dialect=` as a consistency
   gap, not a broken contract.
4. `resolve_contextual` and LF-only dialects: the first report generalized
   the trailing-CR loss to all LF-only dialects. Compose reads
   `A=x\r\r\n` as `x`, so the observed loss is specific to Docker and other
   raw-value LF-only dialects.
5. `Document::example` and the BOM: the first report said the BOM is dropped.
   Under `Keep` the whole first declaration is commented out, and under
   `Error` the invalid item becomes `#`; both lose the BOM. State the full
   effect.
6. `QuotedTail::Append`: the token span is the quoted token only, while the
   entry span includes the tail. The first report described this correctly,
   but the tail is also not normalized and is not scanned for warnings. Keep
   both parts together.
7. DOTENV_EXPAND: the first report stated a difference as a fact without a
   version. The observation is against dotenv-expand 1000.0.0. The actionable
   item is the missing pin and oracle.
8. `parse` trie memory and `Reference::argument` were raised during the
   review and then dropped after verification. The trie measurement was not
   reproduced with shared key prefixes, and `${VAR:-}` returns
   `Some(7..7)`, not `None`. They are not findings.
9. The first report did not mention that every `ExpandOptions` preset keeps
   unresolved references literal, while Compose and dotenv-expand substitute
   empty. This is a documented choice for the rules presets, but the resolution
   conformance profile must select `Unresolved::Empty` or use inputs where
   every name is set.

## Release plan

### 1.1.1

1. AUD-1: contextual loaded resolution exactness. Fixed on the `prep-1.1.1`
   branch.
2. AUD-2: Compose and dotenv-expand operand grammar, with oracle-backed tests. Fixed on the `prep-1.1.1` branch.
3. AUD-3: no-change guard for `fmt --write` and `set`.
4. AUD-5: `diff` header for two files.
5. AUD-6: recursive discovery reporting and deduplication.
6. AUD-7: `FinalNewline::Remove` idempotence.

Each fix needs a regression test. The release also needs the full gate,
`check_docs.py`, conformance, and a fuzz run. The 1.0.1 patch precedent covers
behavior fixes in a patch release.

### 1.2.0

- AUD-4: identity check for reads and replaces.
- AUD-8, AUD-9 and AUD-10: resource bounds for commands, reference scanning
  and diagnostics. These add builders and are minor-version changes.
- Value masking for `Debug`, `diff` and serde errors, which is already on the
[After 1.0](1.0-fix-round.md#after-10) list.
- AUD-11 through AUD-24, with Windows coverage for the write path, `run`
  environment, command quoting and environment key rules.
- AUD-23 and AUD-25: pin dotenv-expand and add a resolution conformance
  profile.

### Companion crates

After 1.1.1, the `adotenv-lint` prototype can start in parallel with the 1.2.0
hardening, because it is a separate crate and the document and edit APIs are
stable. Start `adotenv-lsp` after the lint rules and value masking are settled,
so the editor protocol does not depend on a moving policy. Keep lint policy and
editor protocol work out of the core.

### Housekeeping

- Update `performance.md` and `test-audit.md` after the 1.1.x changes.
- Run mutation testing on the 1.1 code.
- Record four scheduled fuzz runs for the release candidate if the 1.0 rule
  applies.
- Close issue 13 and file the AUD items that are not already tracked.
- Fast-forward local `main`, remove stale branches, and work on `prep-1.1.1`
  or the next release branch.

## Evidence appendix

Commands used for the measurements in this page:

```console
# coverage
cargo llvm-cov --workspace --all-features --locked --summary-only

# conformance
python3 conformance/check_adotenv.py --setup

# memory, release build, value of 100,000 and 200,000 repeated ${M:-$A}
./target/release/mem4 resolve 100000
./target/release/mem4 resolve 200000

# diagnostics, 1 MB value of #
./target/release/mem2 warn_parse
./target/release/mem2 warn_values

# lookup index, 200,000 Node bare keys
./target/release/mem2 bare_parse
./target/release/mem2 bare_index
```
