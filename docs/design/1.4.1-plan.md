# 1.4.1 / linter 0.2.0 / LSP 0.4.0 plan

Status: release preparation complete. Benchmark foundation (#73-#77), the #78
optimization with the accepted retained no-loss result, linter config
(#80/#81), mutation and differential fuzz hardening (#82/#83), and release
attestation (#71 implementation) have landed. Benchmark methodology and
per-release evidence (#79) are published, and #84 is complete on `main`.
Tagging and publication remain pending explicit approval.

This release cycle combines a reproducible competitive benchmark lab, concrete
hardening work and one focused editor feature. The core release is a patch
because the selected work is internal performance, correctness and tooling, not
a new core API. `adotenv-lint` gains a reusable configuration API and
`adotenv-lsp` gains explicit lint configuration.

## Decisions

- Compare adotenv only on feature-comparable modes: value parsing, file
  loading, literal resolution and their memory footprints. Lossless document,
  edit, format and sort workloads are internal-only because competitors do not
  retain the same state.
- The release target is a **strict win in every comparable speed, peak-heap and
  allocation cell**, with retained heap **no worse than every competitor**,
  using medians and confidence intervals. A strict retained-heap win would
  require a new compact values API and is deferred to a later minor release.
- Competitors are pinned: `dotenvy` 0.15.7, `dotenv` 0.15.0, `dotenvs` 0.2.2,
  `dotenv-parser` 0.1.3 and `dotenv-flow` 0.16.2. `dotenv-ng` 1.0.0 is optional
  for compatible load/CLI cells only.
- Memory uses an isolated-process counting allocator for peak/retained heap and
  allocations, plus RSS where available. Linux is the reference platform and a
  Valgrind/DHAT cross-check covers a sample.
- Internal regressions are gated by deterministic instruction/cycle and
  allocation counts on Linux. Competitor wall-time is release evidence, not a
  PR gate.
- Publication-grade runs execute on `kbench` through the shared benchq pueue
  daemon (`PUEUE_CONFIG_PATH=/etc/benchq/pueue.yml`; group `bench`, one slot).
  Tasks are serialized; no host-wide tuning or other projects' queue changes.
- `adotenv-lsp` defaults to no lint policy. `--config <path>` is explicit;
  `--discover-lint-config` is the only opt-in discovery mode.

## Benchmark contract

### Comparable matrix

- Fixture sizes: 8, 128, 1,000, 10,000 and 100,000 entries.
- Shapes: plain assignments; quoted and escaped values; Unicode, BOM and CRLF;
  comments/export/bare keys; duplicates; malformed recovery; multiline values;
  long lines; references/operators; conformance-derived realistic inputs.
- Modes: values parsing, file loading, literal resolution, and their peak and
  retained memory.
- Internal modes: lossless parsing, lookup, references, resolve, edits,
  formatting, sorting, comparison and CLI startup/check.
- Every case records the exact fixture hash, package versions, feature flags,
  rustc, OS, CPU, load and command line.

### Metrics

- Speed: criterion medians with confidence intervals for libraries and
  hyperfine for CLI cells; minimum work per sample must be large enough to keep
  noise below the reported margin.
- Memory: peak live heap, retained live heap, allocation count and RSS.
- Internal regressions: deterministic `Ir`/cycles and allocation counts.
- Publication: JSON plus Markdown under `docs/benchmarks/`, with a fingerprint
  header and a result schema.

### Host and execution

- Canonical host: `kbench` over SSH.
- Queue: pueue/benchq configuration at `/etc/benchq/pueue.yml`, group `bench`,
  one parallel slot. Queue one complete run at a time.
- Do not stop, reconfigure or quiesce other projects' services, CI runners or
  host-wide CPU/swap settings.
- Record load and fingerprint; reject publication runs that fail the
  fingerprint or noise checks.

## Risks and boundaries

- A strict win on every tiny input may be dominated by fixed setup costs. The
  harness must use enough work per sample and report uncertainty; retain
  no-loss cells rather than silently dropping them. Retained-heap ties are
  explicitly accepted for this patch release.
- Some competitor shapes are not semantically comparable. Exclude them with an
  explicit reason; never count an unsupported run as a win.
- kbench is shared. Serialize through pueue and accept scheduling delay rather
  than changing host settings.
- Keep the core dependency-free and `no_std`; benchmark-only crates and
  competitor dependencies stay out of the published core.
- If the benchmark work reveals a public core API addition, re-open the
  core-version decision instead of shipping it as 1.4.1.
