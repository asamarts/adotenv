# 1.5.0 plan

Status: release preparation complete. The compact values API is implemented
and its publication-grade memory evaluation was rerun from release-candidate
SHA `0a9fc92`. Tagging and publication remain pending explicit approval.

## Scope

`1.5.0` is a minor release because it adds a public core API. It does not change
the existing map-based `parse_values`, `load_values` or document APIs.

The release adds:

- `CompactValues`, `parse_values_compact`, `parse_values_compact_with` and
  `parse_values_compact_with_options`;
- compact loading variants for cascades and file lists;
- a masked `Debug` form for compact values;
- the `--compact` benchmark matrix and its publication-grade memory evidence.

The linter and LSP keep their compatible `adotenv` requirements; they do not
need a new release for this core minor.

## Decisions

- Keep `parse_values` and `load_values` map-backed by default. Compact values
  are opt-in for callers that care about retained memory.
- The compact matrix is the 1.5.0 memory evidence. It covers values and load
  cells only; it does not add a speed claim.
- Retained heap is a strict win in all 20 non-empty values/load cells, a
  zero-byte tie in the 10 empty cells, and a loss in none. Peak heap and
  allocation count win all 30 cells against the best pinned competitor.
- The published 1.4.1 map-based speed and memory claims remain historical
  evidence and are not rewritten.
