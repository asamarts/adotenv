# 1.8.0 and LSP stabilization plan

Status: planned. Tracking issues:
[#248](https://github.com/asamarts/adotenv/issues/248) (`adotenv-lsp 0.6.0`
stabilization), [#249](https://github.com/asamarts/adotenv/issues/249) (`adotenv
1.8.0` additive core APIs),
[#250](https://github.com/asamarts/adotenv/issues/250) (remaining After-1.0 edge
cases), and [#251](https://github.com/asamarts/adotenv/issues/251)
(`adotenv-lint 0.3.0`).

## Scope

This cycle has three coordinated tracks:

1. Graduate `adotenv-lsp` out of unstable prototype status into a
   semver-checked `0.6.x` line.
2. Ship additive `1.8.0` lockstep capabilities in `adotenv`, `adotenv-process`
   and `adotenv-cli` while keeping the core `no_std`, dependency-free, Rust 1.81
   compatible and semver-compatible with 1.x.
3. Follow up with `adotenv-lint 0.3.0` on top of `adotenv 1.8.0` for schema
   rules and bounded fix application.

## Track 1: `adotenv-lsp 0.6.0` stabilization (`#248`)

### Version-line policy

`adotenv-lsp` stays on its own `0.x` line (starting with `0.6.0` as the first
semver-checked release) rather than jumping to `1.0.0`. Its public library API
exposes `lsp-types` 0.x directly, so following the same rule used by
`adotenv-config` and `adotenv-figment`, an upstream `lsp-types` minor bump
remains a `0.x` minor release of `adotenv-lsp` instead of causing major-version
churn.

### Non-breaking groundwork landed ahead of `0.6.0`

- Monotonic position mapping when a diagnostic span lands between `\r` and `\n`
  of a CRLF line ending (such as an unknown escape `"\\\r\n"`), plus full
  UTF-16 surrogate-pair width when anchoring stripped BOM diagnostics.
- Accurate `BomPolicy::Error` column mapping and zero-width BOM diagnostics on
  BOM-only or BOM+newline inputs.
- Recovering parse in `rename_with_options` (preserving parse-limit errors while
  allowing renames in files with unrelated syntax errors) and single-entry
  narrowing in `reference_at`.
- Multiline, backtick, Compose colon, Python escaped-single-quote, raw-value,
  escaped-dollar and braced dotted-reference fixes in completion, plus multiline
  key escaping in Markdown hover output.
- LSP 3.17 protocol compliance in the stdio binary: `serverInfo` in `initialize`,
  document `version` in `textDocument/publishDiagnostics`, non-zero exit when
  `exit` arrives before `shutdown`, rejection of `didChange` on unopened URIs,
  explicit transport-error propagation, scheme-aware and Windows drive-letter
  URI ignore matching, and CLI `--dialect`, `--max-items` and
  `--max-diagnostics` flags.
- Additive library polish: `EditError` and `BomPolicy` re-exports,
  `LspOptions::without_lint_options`, `Clone`/`PartialEq`/`Eq` on
  `RenameError`, and runnable crate and README doctests.

### Remaining freeze criteria for `0.6.0`

1. **Public API symmetry and session handle**: decide whether to unify the
   16 free-function surface (`diagnostics` and `hover` require `&LspOptions`,
   while seven other operations provide both default and `_with_options`
   wrappers) and whether to expose a stateful `Session` or parsed document
   handle so callers do not re-parse and rebuild `LineIndex` on every request.
2. **Protocol semantics decisions**: decide whether `apply_change*` adopts LSP
   3.17 column clamping (`character > line_len`) instead of returning `None`, and
   whether `references*` returns `reference.name` spans instead of full
   `${VAR:-default}` spans.
3. **Bounded transport and dependency hygiene**:
   - Bound incoming header lines and `Content-Length` allocations before parsing
     frames so oversized payloads cannot trigger OOM ahead of parse limits.
   - Gate `lsp-server` behind a default-on `stdio` feature
     (`[[bin]] name = "adotenv-lsp" required-features = ["stdio"]`) so library
     embedders do not depend on `lsp-server` or `crossbeam-channel`.
   - Relax exact pins (`lsp-types = "0.97"`, `lsp-server = "0.10"`) and raise
     the `adotenv` floor to at least `1.7.3` (or `1.8.0`).
4. **Editor capabilities**: add `textDocument/prepareRename`,
   `textDocument/formatting` (`Document::format`), `textDocument/codeAction`
   (`adotenv-lint::Finding::fix` / `apply_fix`), optional LSP 3.17
   `positionEncoding` negotiation, and workspace-folder config discovery for
   `--discover-lint-config`.
5. **CI and documentation graduation**: add `--package adotenv-lsp` to
   `cargo semver-checks check-release` in CI, re-evaluate inclusion in the
   minimal-versions check, and remove prototype caveats across the README,
   [Language server](lsp.md), [Quality](quality.md),
   [Feature decisions](feature-decisions.md), [Architecture](architecture.md)
   and `ROADMAP.md`.

## Track 2: `adotenv 1.8.0` lockstep additions (`#249`, `#250`)

All core additions stay additive and preserve 1.x semver compatibility,
`no_std` builds and the Rust 1.81 MSRV:

1. **`CompactEntries` loaders and process helpers (`#249`)**:
   - Add `load_cascade_entries_compact`, `load_cascade_entries_compact_with`,
     `load_cascade_entries_compact_with_options`, `load_entries_compact` and
     `load_entries_compact_with_options` under the `load` feature, matching the
     `CompactValues` loader family while keeping bare declarations.
   - Evaluate `adotenv-process::{validate_compact_entries, apply_compact_entries}`
     with explicit bare-entry semantics.
2. **Bounded edit, format and sort helpers (`#249`)**:
   - Add `Document::{comment,uncomment,set_export}_with_options` accepting
     `EditOptions`.
   - Add `Document::format_with_options(&FormatOptions, EditOptions)` and
     `Document::sort_with_options(EditOptions)` with pre-allocation byte and
     line caps and bounded verification/reference scanning (closing the `AUD-9`
     caveat in [1.1 audit](1.1-audit.md)).
3. **Multi-BOM support on `LineIndex` (`#249`)**:
   - Add `LineIndex::with_bom_policy(BomPolicy)` so `BomPolicy::Strip`,
     `BomPolicy::StripAll`, `BomPolicy::Keep` and `BomPolicy::Error` share one
     core position-mapping implementation across `adotenv`, `adotenv-cli` and
     `adotenv-lsp`.
4. **Remaining After-1.0 edge cases (`#250`)**:
   - Formatting idempotence under custom `line_byte_limit` with
     `LineBreaks::Lf`, and Python quote-style formatting for a `\u{feff}export`
     key (see [1.0 fix round](1.0-fix-round.md)).
   - Serde non-string map keys (such as `BTreeMap<u16, String>`) and typed
     non-string fields inside `#[serde(flatten)]`.
   - Evaluate `Document::example` output for Compose text directly following a
     closing quote (currently emitted as a bare key on its own line).

## Track 3: `adotenv-lint 0.3.0` follow-up (`#251`)

- Add opt-in schema / `.env.example` presence-and-shape rules (keeping parser
  core policy-free; see [Feature decisions](feature-decisions.md)).
- Wire `apply_fix`, `apply_fixes` and `apply_batch` to `adotenv 1.8.0`'s
  bounded `edit_with_options`, `format_with_options` and `sort_with_options`.

## Release verification checklist

Before tagging `v1.8.0` or dispatching `adotenv-lsp 0.6.0` / `adotenv-lint 0.3.0`:

1. Pass all CI jobs (`fmt`, `clippy`, `docs`, `supply chain`, `public API semver`
   including `adotenv-lsp`, cross-platform tests, `MSRV` 1.81 / 1.85 / 1.88,
   `minimal versions`, `package`, `benchmark smoke`, `deterministic perf`,
   `alloc-only core`, `conformance` and `Docs` headless-browser smoke).
2. Run focused `--in-diff` mutation sweeps on the dedicated remote validation
   host (one worker, 8 GiB cap; see [Heavy validation](heavy-validation.md))
   and close all genuine test gaps.
3. Run four clean seven-target `fuzz.yml` workflow runs on the release commit
   when core parser, edit, format, encoding or limit code changes.
4. Record clean-SHA memory and speed benchmark matrices on the reference host
   through its single-slot serialized queue and publish `RESULTS-1.8.0.md`.
5. Verify crates.io, docs.rs, GitHub Release SHA-256 checksums and Sigstore
   build-provenance attestations for every published crate.
