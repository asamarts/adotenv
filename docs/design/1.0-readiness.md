# 1.0 readiness

A 1.0 release requires all of the following.

Current release: **0.10.4**.

## Criteria

| Item | Status |
|---|---|
| Workspace quality gate | Complete: 416 tests, no_std, MSRV, docs, package, semver, supply-chain, coverage and mutation gates |
| Conformance corpus | Complete for the current corpus: 80 cases and 20 profiles |
| Manual performance record | Complete on kbench |
| Sustained fuzzing | In progress: 1 of 4 scheduled runs |
| External adopter | Complete: alint, a separate public repository |
| CLI and library contracts | Frozen |

## Required evidence

1. Re-run the release gate from [quality.md](quality.md), including the
   supply-chain and semver checks.
2. Record an idle-host performance run and compare it with
   [performance.md](performance.md) and
   [benchmark-dashboard.md](benchmark-dashboard.md).
3. Confirm four consecutive controlled fuzz runs for all five targets after the
   last parser, edit, encoding, resolution or formatting change. The first run
   passed on 2026-10-26. Four host-scheduled runs use
   `scripts/dispatch_fuzz.sh` at 06:00, 07:00, 08:00 and 09:00 EDT; each run
   records its workflow run ID, timestamp and conclusion.
4. Confirm at least one external project uses a published adotenv crate, with
   the maintainer's confirmation and the version and features used.
5. Verify the tag, crates.io versions, docs.rs builds and GitHub Release.

## External adopter

- Project: [`asamarts/alint`](https://github.com/asamarts/alint), a separate
  public repository.
- Adotenv version: 0.10.4, default features.
- Use: literal dotenv parsing, diagnostics, spans and native verified edits in
  alint-core.
- Compatibility finding: upgrading from adotenv 0.2.1 required no alint source
  changes.
- Verification: 887 alint-core tests and 270 alint CLI tests pass; Cross-Platform
  CI and the quality jobs pass.

## Fuzz rule

An ad hoc manual fuzz run does not count toward the four runs. A host-scheduled
timer run counts when its workflow run ID, scheduled time and conclusion are
recorded before release. A skipped, cancelled or failed run does not count. A
fuzz-relevant code change restarts the count.

## Adopter rule

An adopter must be outside this repository and must use a published crate.
Downloads, stars and issue comments do not qualify. Public attribution is
optional; the maintainer confirmation must be recorded.
