# 1.0 readiness

This page records the evidence behind the 1.0.0 release of `adotenv`,
`adotenv-process` and `adotenv-cli` on 2026-10-31. `adotenv-config` and
`adotenv-figment` were released as 0.12.0 at the same time.

The first evidence set was collected on 0.10.4. The
[1.0 fix round](1.0-fix-round.md) then changed parser, edit and resolution
behavior, so the evidence was collected again on the fixed code.

## Criteria

| Item | Status |
|---|---|
| Workspace quality gate | Passed on the release commit, locally and in CI |
| Conformance corpus | Passed: 80 cases and 20 profiles |
| Manual performance record | Recorded on the reference host on 2026-10-31 from `0a2e5c5`; see [performance.md](performance.md) |
| Sustained fuzzing | 4 consecutive scheduled runs on `0a2e5c5`, 2026-10-31 |
| External adopter | alint, confirmed on 0.11.0 |
| CLI and library contracts | Frozen after the fix-round decisions |

## Evidence

1. The CI gate described in [quality.md](quality.md) passed on the release
   commit `c695b8d`, including the supply-chain and semver checks.
2. The performance record was taken on the reference host on 2026-10-31 and
   compared with the 0.10.4 record. The budgets were checked in the same
   session against 0.10.4; the one change is described in
   [performance.md](performance.md#budgets).
3. Four scheduled fuzz runs completed successfully on 2026-10-31, each covering
   all five targets on commit `0a2e5c5`:
   - 21:00 UTC: run 41241485793
   - 21:15 UTC: run 41242695945
   - 21:30 UTC: run 41243864595
   - 21:45 UTC: run 41245024633

   Each was a `workflow_dispatch` run started on a fixed schedule. Runs on
   earlier commits of the fix round do not count, because later fuzz-relevant
   changes restarted the count. The release commit changed only versions and
   documentation after `0a2e5c5`.
4. alint used the published crate; see below.
5. After publishing, the tag, the crates.io versions of all five crates, the
   docs.rs builds of the four libraries and the GitHub Release were verified.

## External adopter

- Project: [`asamarts/alint`](https://github.com/asamarts/alint), a separate
  public repository.
- adotenv version: alint `main` depends on 0.10.4 with default features.
  alint's tests also pass against the published 0.11.0 with no source changes:
  2,561 tests in `alint-core`, `alint-rules` and `alint` on 2026-10-31.
- Use: literal dotenv parsing, diagnostics, spans and native verified edits in
  `alint-core`.
- The rename collision rule and the reference-scanning performance change
  shipped after 0.11.0, in 1.0.0. alint's edits use only `Edit::Set` and
  `Edit::Remove`, which the rename change does not affect.

## Fuzz rule

An ad hoc manual fuzz run does not count toward the four runs. A scheduled run
counts when its workflow run ID, scheduled time and conclusion are recorded
before release. A skipped, cancelled or failed run does not count. A
fuzz-relevant code change restarts the count.

## Adopter rule

An adopter must be outside this repository and must use a published crate.
Downloads, stars and issue comments do not qualify. Public attribution is
optional; the maintainer confirmation must be recorded.
