# 1.0 readiness

A 1.0 release requires all of the following.

Current release: **1.0.0** for `adotenv`, `adotenv-process` and `adotenv-cli`;
**0.12.0** for `adotenv-config` and `adotenv-figment`.

The first evidence set was collected on 0.10.4. The
[1.0 fix round](1.0-fix-round.md) changed parser, edit and resolution behavior,
so every item was collected again on the fixed code before the tag.

## Criteria

| Conformance corpus | Passed: 80 cases and 20 profiles |

## Evidence

1. The release gate from [quality.md](quality.md) passed on the release commit,
   including the supply-chain and semver checks.

   compared with the 0.10.4 record. The engineering budgets were checked in the
   same session against 0.10.4; the one change is described in
   [performance.md](performance.md).
3. Four host-scheduled controlled fuzz runs completed successfully on
   2026-10-31, each covering all five targets:
   - 17:00 EDT: run 41241485793
   - 17:15 EDT: run 41242695945
   - 17:30 EDT: run 41243864595

   Each run is a `workflow_dispatch` event recorded on commit `0a2e5c5`, fired
   by a one-shot timer on the maintainer host. Runs on earlier commits of the
   fix round do not count, because later fuzz-relevant changes restarted the
   count.
4. alint uses the published crate; see below.
5. The tag, crates.io versions, docs.rs builds and GitHub Release are verified
   after publishing.

The 0.10.4 evidence set is in the history of this file.

  changes.

## Fuzz rule

An ad hoc manual fuzz run does not count toward the four runs. A host-scheduled
timer run counts when its workflow run ID, scheduled time and conclusion are
recorded before release. A skipped, cancelled or failed run does not count. A
fuzz-relevant code change restarts the count.

## Adopter rule

An adopter must be outside this repository and must use a published crate.
Downloads, stars and issue comments do not qualify. Public attribution is
optional; the maintainer confirmation must be recorded.
