# 1.0 readiness

A 1.0 release requires all of the following.

Current release: **0.10.4**.

## Criteria

| Item | Status |
|---|---|
| Workspace quality gate | Complete: 341 tests, no_std, MSRV, docs, package and semver |
| Conformance corpus | Complete for the current corpus: 80 cases and 20 profiles |
| Manual performance record | Complete on kbench |
| Sustained fuzzing | In progress: 1 of 4 scheduled runs |
| External adopter | Pending: no independent record |
| CLI and library contracts | Frozen |

## Required evidence

1. Re-run the release gate from [quality.md](quality.md).
2. Record an idle-host performance run and compare it with
   [performance.md](performance.md) and
   [benchmark-dashboard.md](benchmark-dashboard.md).
3. Confirm four consecutive scheduled fuzz runs for all five targets after the
   last parser, edit, encoding, resolution or formatting change. The first run
   passed on 2026-10-26; the next dates are 2026-11-02, 2026-11-09 and
   2026-11-16.
4. Confirm at least one external project uses a published adotenv crate, with
   the maintainer's confirmation and the version and features used. No
   independent record is currently claimed.
5. Verify the tag, crates.io versions, docs.rs builds and GitHub Release.

## Fuzz rule

A manual fuzz run does not count toward the four scheduled runs. A skipped,
cancelled or failed run does not count. A fuzz-relevant code change restarts the
count.

## Adopter rule

An adopter must be outside this repository and must use a published crate.
Downloads, stars and issue comments do not qualify. Public attribution is
optional; the maintainer confirmation must be recorded.
