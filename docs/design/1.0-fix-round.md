# 1.0 fix round

A pre-release audit on 2026-10-30 found defects in behavior that 1.0 would
freeze. They are fixed in 0.11.0. The 1.0 evidence in
[1.0-readiness.md](1.0-readiness.md) is then collected again on the fixed code.

Every fix needs a regression test that fails on the 0.10.4 code.

## Decisions

| Topic | Decision |
|---|---|
| CLI exit codes | `0` success, `1` findings (diagnostics, differences, required formatting, a missing `get` key), `2` usage, I/O failure or input the command cannot process, for every command. |
| Insert collisions | `Edit::Insert` rejects a key that already exists or that another edit in the batch creates, like `Rename`. Removing that key in the same batch frees it. |
| Sort and references | When one key references another in the same group, sort keeps their current relative order. Resolved values do not change under sequential or whole-file scope. |
| Adapter versions | `adotenv`, `adotenv-process` and `adotenv-cli` go to 1.0. `adotenv-config` and `adotenv-figment` keep their own 0.x line, so a new major of `config` or `figment` is a 0.x minor release. |
| `config` version | `adotenv-config` moves to `config` 0.15 with its own MSRV of 1.88. The core MSRV stays 1.81. |
| Reference containers | `Reference` names its innermost container by index into the same list instead of carrying the whole container chain, so `Entry::references` stays linear in memory. `Reference::is_eligible` keeps its signature. |
| Loaded resolution scope | `LoadedEnvironment::resolve_contextual` rejects sequential scope with the error `resolve_decoded` already returns. Winning declarations come from different files, so no single order defines sequential bindings. |

## Core parser and model

These changes are fuzz-relevant and restart the controlled fuzz count.

- [x] P1. Node and Python: blank and whitespace-only lines become `Blank` items
  instead of leading whitespace of the next statement. Groups, leading comments,
  removal, sorting, blank-line collapsing and portability then agree with the
  other presets.
- [x] P2. Compose: a quoted entry's item extends over the rest of its physical
  line (trailing whitespace, inline comment and line ending) when no further
  statement follows on that line. Sorting, inserting, removing, formatting and
  example generation then keep line structure.
- [x] P3. Parse time stays linear when many statements share one physical line
  (Compose and Node).
- [x] P4. Reference scanning stays linear for long `$` runs and deep nesting.
- [x] P5. Diagnostic line numbers account for line breaks in leading whitespace
  before quoted keys in custom dialects.
- [x] P6. `Entry::references` uses memory linear in the value length (decision
  above). Before, `n` nested forms produced about `n * n / 2` container records,
  which `sort`, `adotenv fmt` and the fuzz targets reach.

## Resolution and loading

- [x] R1. Resolution enforces a total budget on resolved provenance, so small
  inputs cannot allocate unbounded memory. A structured error reports the limit.
- [x] R2. Resolution time stays linear in the number of references in one
  value.
- [x] R3. `LoadedEnvironment::resolve_decoded` resolves loaded keys exactly as
  loaded. A key that the synthetic document cannot represent is a structured
  error, never a different key.
- [x] R4. `LoadedEnvironment::resolve_contextual` rejects sequential scope
  (decision above), so a reference to a key that a later cascade file
  overrides is never left unresolved.

## Edits, formatting and sorting

- [x] E1. `Edit::Insert` rejects key collisions (decision above).
- [x] E2. Sort keeps the relative order of referencing pairs (decision above).
  The README and rustdoc example change accordingly.
- [x] E3. Sort handles a last group that has no final line ending.
- [x] E4. Batches that set an entry and insert after it stay linear.
- [x] E5. Documentation states that text edits apply in reverse order of the
  returned slice. Edits that start at the same offset are ordered.

## CLI

- [x] C1. Temporary files for `fmt --write` and `set` are created with
  restrictive permissions before any content is written, then receive the
  target's permissions.
- [x] C2. Exit codes follow the decision above. The frozen exit-code test and
  `cli.md` agree.
- [x] C3. `run` reports a child killed by a signal as `128 + signal` on Unix and
  never maps a failing Windows status to `0`.
- [x] C4. `load` prints values encoded so the output parses back to the same
  values.
- [x] C5. `fmt --write` and `set` on a symlink replace the link target and keep
  the link.

## Documentation

- [x] D1. `cli.md` lists every JSON field, including `ok`, `error` and the
  diagnostic object.
- [x] D2. The README describes what `run` passes to the child, that `diff`
  prints values, and that `Debug` output includes values.
- [x] D3. `ExpandOptions::compose` is documented as Compose-style reference
  rules, not a full Compose interpolation emulation.
- [x] D4. `DoubleEscapes` rustdoc shows single backslashes.
- [x] D5. Mode-name rules in `loading.md` match the implementation.

## Tests and fuzzing

- [x] T1. The resolution fuzz target also runs with default limits.
- [x] T2. Parser and resolution fuzzing include long single-line inputs.
- [x] T3. An invariant test checks that blank-line groups agree across presets
  for inputs that every preset reads the same way.
- [x] T4. Format fuzzing covers trimming with the final newline preserved,
  blank-line collapsing with quote styles, and `QuoteStyle::Unquoted`.

## After 1.0

Tracked for 1.x, not part of 0.11:

- Windows: `exec::Shell` argument quoting for `cmd /C`, and the process
  environment value length limit in `adotenv-process`.
- A lone CR at the end of a CRLF file in LF-only dialects.
- Serde errors that report an empty key.
- Optional value masking for `Debug`, `diff` and serde errors.
- Formatting idempotence with custom line limits and LF-only line breaks.

## Release sequence

1. Land the items above with regression tests.
2. Release 0.11.0 for all five crates.
3. Confirm alint on 0.11.0.
4. Run four consecutive controlled fuzz runs on the release code.
5. Re-run the reference-host performance record.
6. Run the release gate and the semver check, then tag 1.0 for `adotenv`,
   `adotenv-process` and `adotenv-cli`.
